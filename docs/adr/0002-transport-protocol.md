# ADR 0002: Вибір протоколів WebSocket та MQTT для передачі даних

**Статус:** Прийнято
**Дата:** 2026-09-28

## Контекст і проблема
Стелаж повинен миттєво оновлювати віртуальний кошик у мобільному застосунку покупця (FR-08) і надійно передавати фінальні чеки на хмарний бекенд для оплати. Необхідно обрати протоколи для цих двох асинхронних потоків.

## Розглянуті альтернативи
1. Використання HTTP REST (Polling / Webhooks) для обох потоків.
2. Використання WebSocket (з JWT-авторизацією) для застосунку покупця та MQTT (QoS 1) для хмарного бекенду.

## Прийняте рішення
Обрано **Альтернативу 2**. Для оновлення кошика використовується захищений WebSocket (забезпечує повнодуплексний зв'язок без накладних витрат HTTP). Для зв'язку з хмарою — MQTT з рівнем якості QoS 1 (гарантує доставку повідомлень).

## Наслідки
* **Позитивні:** Відсутність мережевих затримок при кожній події зважування (задовольняє NFR-01). MQTT дозволяє буферизувати транзакції під час втрати зв'язку та автоматично відновлювати відправку (NFR-05).
* **Негативні:** Оскільки MQTT QoS 1 гарантує доставку "хоча б один раз", можливе дублювання повідомлень. Це вимагає реалізації строгих механізмів ідемпотентності на боці хмарного білінгу, щоб уникнути подвійних списань коштів.
